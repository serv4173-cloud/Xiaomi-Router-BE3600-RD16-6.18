# Установка OpenWrt на Xiaomi BE3600 RD16

**Статус: не проверено на устройстве.** Ни один шаг ниже ещё не выполнялся на железе. Любая запись в NAND и любое изменение переменных U-Boot требуют UART на 1,8 В.

## Известные факты

| Что | Значение | Как получено |
|---|---|---|
| Слот стока | mtd19 `rootfs`, `ubi.mtd=rootfs` | `/proc/cmdline` на роутере |
| Флаги на стоке | `flag_boot_rootfs=0`, `flag_boot_success=1`, `flag_try_sys1_failed=0`, `flag_try_sys2_failed=0` | `nvram get`, только чтение |
| Тома mtd19 | `kernel` 83 LEB, `ubi_rootfs` 193 LEB | `/sys/class/ubi/ubi0_*` |
| Слот под OpenWrt | mtd20 `rootfs_1`, `flag_boot_rootfs=1` | схема по дампу `APPSBLENV` и RomikB |
| Раскладка томов mtd20 | `kernel` 40, `ubi_rootfs` 133, `rootfs_data` 143 LEB | **наша оценка**, не проверена |
| NAND | W25N01KWZEIG, страница 2048, OOB 64, erase 128 KiB | дамп и `/proc/mtd` |

## Что не проверено

- Принимает ли U-Boot arm64-FIT и какую конфигурацию запрашивает (`config@1` или `config@mi04.1-c2`).
- ECC: в DTS 8/512 по аналогии с RD15, на стоке 4/512. Ошибка ECC портит данные.
- Автооткат по `flag_try_sys*_failed`: в APPSBL найдены только строки.
- Достаточность 40 LEB под `kernel` и поведение `ubirsvol` для статического тома.
- Имя MTD `0:appsblenv` и размер env для `fw_env.config`.
- `board-id` в `bdwlan.b0060` (QCN6432).

## Условия остановки

Остановиться и не продолжать, если выполнено любое из условий:

- UART не показывает приглашение U-Boot.
- На линии TX больше 1,8 В (проверить мультиметром до подключения).
- RAM boot завершается паникой ядра или не видит NAND.
- ECC-ошибки в логе ядра при чтении mtd19 или mtd20.
- Не удаётся вернуть `flag_boot_rootfs=0` и загрузить сток.

## Подготовка

1. Скопировать `D:\openwrt_rd_16\backup` (24 раздела MTD) на внешний носитель. Дампы содержат MAC, калибровку и Wi-Fi пароли, публиковать их нельзя.
2. Сменить пароль root на стоке и в старой сборке mtd20 (он был открытым текстом в чате).
3. Скачать артефакты CI и сверить SHA256 с `sha256sums`.
4. Подключить UART: только GND, TX, RX. VCC не подключать. Адаптер FT232RL переключить на 1,8 В, уровень на TX измерить мультиметром до подключения к плате.

## Шаг C1. Загрузка из RAM (без записи в NAND)

1. Снять лог U-Boot по UART (115200 8N1), сохранить его целиком.
2. Загрузить initramfs `.itb` через TFTP в RAM и запустить `bootm` с явным выбором конфигурации. Начать с `config@mi04.1-c2`, если U-Boot не примет его, проверить `config@1`.
3. После загрузки проверить: `dmesg | grep -i -E 'nand|ecc|ubi'`, `cat /proc/mtd`, `ip link`, `dmesg | grep -i -E 'ath12k|q6|wcss'`.
4. Не вызывать `ubiformat`, `flash_erase`, `nandwrite`, `fw_setenv`.

Результат C1 определяет, имеет ли смысл идти дальше. Если ECC или NAND не работают, исправлять DTS, а не записывать образ.

## Шаг C2. Запись в mtd20

Только после успешного C1 и отдельного подтверждения команды. Записывается только mtd20, mtd19 и загрузчик не трогаются.

- Образ для `ubiformat`: `factory.ubi`. Файл `sysupgrade.bin` для этого не подходит.
- Перед записью сверить, что целевой MTD называется `rootfs_1` и что на нём нет ожидаемых данных, которые нужны (он содержит сборку RomikB, её дамп есть в бэкапе).

## Шаг C3. Переключение слота

Только после C2 и отдельного подтверждения. Меняется `flag_boot_rootfs` с 0 на 1. Для отката вернуть значение 0. Чтобы откат работал без загрузки ядра, нужен UART: из U-Boot значение меняется командой `setenv` и `saveenv`.

Автооткат при неудачной загрузке не доказан, на него не полагаться.

## Sysupgrade

Отключён (`RD16_UPGRADE_ENABLED=0`, `platform.sh` отказывает). Включать только после подтверждения раскладки томов на железе.
